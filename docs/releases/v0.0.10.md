# v0.0.10 — Studio, Jump Anywhere, and a Rust core

This line turns Origin Studio from a Linux app with agents into a workspace that explains
itself: one Studio screen for environments, agents, usage and scheduled work; one shortcut
that reaches anything; and a small Rust core that answers the same questions from a
terminal.

The app stays lightweight. The universal layer gains two Rust binaries beside the signed
APK, the companion, the Node CLI and the SBOM.

## Why Origin Studio is unique

- **One workspace, several windows.** A project is plain files with a versioned manifest and
  a hash-chained history. It opens in the Android app, the companion, the Node CLI and the
  Rust core without conversion.
- **Two honest environments, one surface.** Debian 13 runs locally on the phone, offline and
  without root. Dakota OS (Bluefin's atomic image) runs on a host you own. The app says which
  one you chose and what each one cannot do.
- **The room, not another agent.** Origin Agent is a built-in profile over the ACP agents you
  already use, with one approvals sheet and no second subscription. Any other CLI agent works
  in an ordinary shell.
- **Small, auditable core.** Environment, agent, Jump, preview, usage and automation decisions
  live in a dependency-light Rust core (serde only) with a matching plain-JVM core. No
  network, no daemon, no vendor account.
- **Honest limits.** PRoot is not a virtual machine, the prompt count is this device's count
  rather than a provider quota, and Dakota is labelled as alpha community software.

## Studio

The first tab is now **Studio**: a compact, scrollable page rather than a settings maze.

- **Environments.** Choose **Debian 13 — Recommended on phones** or **Dakota OS — Most
  Recommended on laptops and hosts**. Each card lists what it is best for and its limits.
  Dakota is paired over the host protocol; it is not silently unpacked into PRoot.
- **Agents.** Origin Agent plus the ACP registry, and a reminder that any CLI agent works.
  The chosen agent becomes the first choice when a new ACP session starts. Switching never
  signs anything out: each agent keeps its own login.
- **Usage and accounts.** A device-local prompt counter with a daily budget, reset at local
  midnight. It is explicitly not a provider quota; real limits stay in each agent's output.
- **Scheduled commands.** Three useful defaults (working-tree check, recent commits, Debian
  updates), each runnable now or on a daily/weekly schedule. A run creates a real shell
  session in the first project, visible afterwards in Fleet. Scheduling works while Origin
  Studio is open; Android does not wake a closed app for it.
- **Device lab and computer use.** The built-in browser is genuinely agent-drivable (open,
  read, click, type, screenshot) through the same MCP server agents already receive. An
  Android emulator beside the chat is on the roadmap for paired hosts with the Android SDK;
  today the preview pane switches between phone and desktop widths.
- **Premium finishes.** Ink, Aurora, Graphite, Verdant and Ember: five grounds with one
  contrast discipline, applied to the Studio surface.

## Jump Anywhere

Press **Ctrl/Cmd+K** anywhere, including inside a terminal, or use the Studio card. One
field ranks projects, chats, shell sessions, environments, agents and actions; arrows move,
Enter opens, Escape closes. Typing still works in the terminal, because the shortcut is
handled before the shell sees the key.

## Composer: files, images and dictation

- **Drag files or images from another app** onto the composer. Images become image blocks;
  text files up to 2 MB become file blocks. Binary data is refused with a message instead of
  arriving as mojibake.
- **Attach any file** with the new file button, not only photos.
- **Dictate** with the system speech recogniser. Spoken words are appended to typed text, so
  the two mix naturally. If the device has no recogniser, the app says so.

## Previews that render

- **PDF** renders in the file viewer with page navigation, using Android's `PdfRenderer`.
- **Markdown** opens as a formatted preview with an outline and a source toggle, including
  headings, lists, quotes, code and inline emphasis.

## Rust core

`rust/origin-core` is a platform-free crate and CLI:

```sh
cargo test --manifest-path rust/origin-core/Cargo.toml   # 30 tests
cargo build --release --manifest-path rust/origin-core/Cargo.toml
./target/release/origin-core fingerprint
./target/release/origin-core environments
./target/release/origin-core recommend --host
./target/release/origin-core why --json
```

Commands: `fingerprint`, `environments`, `recommend`, `agents`, `themes`, `preview`,
`outline`, `next-run`, `jump` and `why`. It has no network access and no state. CI runs its
tests, and the release ships `origin-core-<version>-x86_64-unknown-linux-gnu.tar.gz` and
`origin-core-<version>-aarch64-unknown-linux-gnu.tar.gz`.

The Android app mirrors the same answers in Kotlin; it does not load Rust at runtime. That
is deliberate: no NDK, no JNI, no extra native payload in the APK.

## Universal layer

Release assets now include the two Rust core archives, checksummed in `SHA256SUMS` and
described under `universal.rustCore` in `release-manifest.json`. The companion zip, Node CLI
tarball and CycloneDX SBOM are unchanged in spirit; the SBOM now lists the Rust core too.

## Honest limits

- PRoot is not a virtual machine: no systemd, no kernel modules, no raw sockets.
- Scheduled commands run while the app is open; there is no background daemon.
- The mobile emulator is a roadmap item for paired hosts, not a bundled emulator.
- Dakota OS is alpha software from the Bluefin community and runs on a host.
- Usage is a local prompt count, not a provider quota. Provider limits remain the agent's
  answer.
- Agent logins belong to each agent. Origin Studio never asks for them.

## Install

1. Download `OriginStudio-0.0.10.apk` and open it.
2. Or add `github.com/OriginLabs1/OriginStudio` to Obtainium.
3. For another screen: unzip `OriginCompanion-0.0.10.zip`, run
   `npx github:OriginLabs1/OriginStudio serve`, or run the Rust core archive directly.

See [`../universal.md`](../universal.md) for the full workflow.

## Requirements

- Android 8.0+ (API 26+), arm64-v8a or x86_64.
- 4 GB RAM recommended; several GB free for Debian and developer tools.
- Internet once on first launch to unpack Debian and fetch developer tools.
